# Phantasmagoria General Platform (CW1)

The General Platform serves as the primary backend API and user interface for the Phantasmagoria system. It handles user authentication, profile management, the alumni bidding engine, and issues API keys for external integrations.

## Setup Instructions

1. **Install Dependencies:**
   ```bash
   npm install
   ```

2. **Environment Configuration:**
   Copy the example environment file and configure the secrets.
   ```bash
   cp .env.example .env
   ```
   Open `.env` and fill in your MySQL database credentials and generate secure keys for `JWT_SECRET` and `SESSION_SECRET`.

3. **Database Initialization:**
   The system expects a MySQL database (or SQLite depending on current config) named `phantasmagoria`. Execute the schema file (if provided) or allow the application to sync.

4. **Run the Server:**
   ```bash
   npm run dev
   ```
   The application will start on `http://localhost:3000`.

## Architecture Details

### Frontend
The frontend is built using Vanilla HTML, CSS, and JavaScript, located in the `public/` and `protected/` directories. It utilizes a stateless architecture relying heavily on the `api.js` utility class to automatically append JWT Bearer tokens to all outbound `fetch` requests.

### Backend
Built with Node.js and Express. Key middleware components include:
- `auth.js`: Verifies JWT tokens and API tokens (`verifyToken`, `verifyApiToken`, `requirePermission`).
- `csrf.js`: Implements custom Double Submit Cookie CSRF protection via an X-CSRF-Token header.

### Background Tasks
- `bidScheduler.js`: A cron job that runs continuously to reset alumni win counts at the start of every month and manages the distribution of the 4th-win bonus slot for event participants.

## Database Schema (Key Entities)

- **`users`**: Core authentication table (id, email, password_hash, role, is_verified).
- **`profiles`**: Extended alumni metadata (first_name, last_name, graduation_year, industry_sector). Links to `users` via `user_id`.
- **`api_tokens`**: Stores securely hashed API keys generated by Developers for third-party systems. Includes granular `permissions` JSON arrays.
- **`token_logs`**: Audit trail tracking every request made using an API token.
